# 我的大学日记（CampusMock）

一个事件驱动的大学新生 AI 互动日记。围绕 AI 黑客松主题“你好，我的大学”，让玩家在网页中经历入学两周的 14 个关键片段，在一页页日记中体验新生的期待、焦虑，以及不同选择带来的变化。

产品展示名采用“我的大学日记”，仓库与技术标识继续使用 `CampusMock`。该定位与每天 1 个事件的内容密度一致，避免产品名称与 MVP 实际内容产生落差。

> 当前已完成 React 前端、Express 游戏接口、DeepSeek 接入、浏览器存档与恢复。已实测连续两天的真实事件生成与结算；完整 14 天和结局流程通过模拟上游回归测试。

## 已确认的项目约束

- **团队与周期**：4 人、5 天，以 Vibe Coding 为主，交付可演示的 MVP。
- **比赛方向**：主题为“你好，我的大学”，评分聚焦 AI 对新生期待与焦虑的预演。
- **内容风格**：以心理治愈和真实共情为主，允许适量轻松表达，但不采用纯搞怪喜剧路线。
- **单局范围**：模拟 14 天，每天 1 个事件，共 14 个事件；原则上不限制现实游玩时长。
- **四维初始值**：学业 0、社交 0、精力 7、金钱 1000。
- **属性变化**：由事件选择决定增减，部分选项影响精力和金钱；不额外设置每日自动恢复或固定扣费。
- **结局方式**：两周事件完成后，四个属性分别按数值大小及正负划分 A、B、C、D 档，再由大模型根据四个档位生成结局标题、详情、评价与建议。
- **核心 AI 亮点**：根据当前游戏天数与玩家属性生成不同事件，并让已有选择影响后续剧情。
- **运行范围**：MVP 仅需支持 localhost 和局域网访问，不要求公网部署。
- **存档要求**：页面刷新或服务重启后可恢复；已使用浏览器 localStorage 保存完整单局快照。
- **API 预算**：主要用于测试和演示，用量较少，暂未指定金额上限。
- **成员分工**：成员 A 负责前端页面与交互，成员 B 负责后端接口与游戏规则，成员 C 负责模型接入与内容生成，成员 D 负责存档、整体集成与协作支持。
- **当前工作范围**：完成各模块实现与联调；演示时长暂不讨论。

## 核心玩法

1. **开始生活**：以学业 0、社交 0、精力 7、金钱 1000 开始第 1 天。
2. **生成事件**：后端调用大模型，结合天数、当前属性及过往选择生成事件。
3. **做出选择**：阅读标题、详情与选项，选择一次行动。
4. **结算变化**：应用模型量化、经过校验并已固定的选项属性增减，保存结果。
5. **继续下一天**：读完结果后推进，每天只结算 1 个事件；等待和重试不推进天数。
6. **生成结局**：第 14 个事件结算后，分别确定四维档位，再由大模型生成结局内容。

属性允许出现负数，负值不提前结束两周体验。已确认采用较宽松分档与较小单次波动，具体阈值和增减范围见游戏规则。

## 首版功能范围

- 开始游戏与 14 天事件推进；游玩过程中显示精力和金钱，隐藏学业与社交数值。
- AI 随机事件、选项及属性变化量化。
- 保存过往事件与选择，使后续生成能够承接已有经历。
- 四维 A～D 分档及 AI 结局标题、详情、评价、建议。
- 浏览器存档、刷新与服务重启后的恢复。
- 生成等待、失败重试，以及防止重复结算。
- localhost 和局域网内的 Web 访问。

首版不包含账号、云端跨设备存档、多人联机、复杂地图、额外支线回合、语音或图片生成。以上首版功能范围与数值规则已冻结，后续如需调整再明确记录。

## 展示与叙事原则

- 页面采用“大学日记”的表达，将每天的事件作为一篇日记或一个关键片段呈现。
- 游玩过程中只展示精力和金钱，学业与社交在后台参与事件生成、属性结算和结局判断。
- 选择前不展示选项的具体数值效果，避免玩家只按收益选择。
- 选择后展示简短结果文案，以及精力和金钱的实际增减；学业和社交的变化通过结果文字与后续事件间接体现。
- 提示词整体采用温和、真诚、具有校园生活细节的心理治愈风格，既承认焦虑，也保留对新生活的期待。

## AI 职责

| 调用场景 | 输入重点 | 生成内容 |
| --- | --- | --- |
| 随机事件生成 | 当前天数、四维属性、过往事件与选择 | 标题、详情、选项；相同天数下不同属性可产生不同事件 |
| 选项结果量化 | 事件情境、选项含义与数值约束 | 每个选项对应的学业、社交、精力、金钱增减 |
| 结局生成 | 四维最终值及各自的 A～D 档位，辅以本局经历 | 结局标题、详情、评价与建议 |

已确认合并生成事件、选项、属性变化及简短结果描述，选择后直接结算。正常一局为 14 次事件调用加 1 次结局调用，共约 15 次，不含重试。前两项不能退化为纯固定事件库；后端负责数据校验、确定性算术与进度，四维档位阈值由规则定义，大模型负责综合档位形成具体结局。

## 本地运行

### 环境要求

- Node.js 20 及以上版本。
- npm 10 及以上版本。
- 在仓库根目录执行命令，依赖由 npm workspaces 统一管理。

### 首次安装与配置

```powershell
npm install
Copy-Item .env.example .env
```

macOS、Linux 或 Git Bash 可使用：

```bash
npm install
cp .env.example .env
```

默认使用 `VITE_API_MODE=server`，前端将请求 Express，并由后端调用 DeepSeek。请在本机根目录 `.env` 中填写 `DEEPSEEK_API_KEY`，模型默认使用 `deepseek-v4-flash`；修改配置后重启后端。未配置密钥时会返回配置错误，如需离线体验请切换为下文的 `mock` 模式。`.env` 已被 Git 忽略，API 密钥不能写入前端代码或提交到仓库。

后端在导入路由前加载根目录 `.env`，路径不受启动目录影响；仅在根目录文件不存在时兼容读取 `server/.env`。终端或部署环境已设置的同名变量优先，不会被文件覆盖。建议统一维护根目录 `.env`，不要给密钥添加 `VITE_` 前缀。模型名称需与 `DEEPSEEK_BASE_URL` 对应的服务商支持列表一致。

若配置后仍不能调用，请先重启后端（修改源码后使用 `npm start` 时还需重新构建），确认 `VITE_API_MODE=server` 并重启前端。`AI_CONFIG_ERROR` 表示缺少有效密钥；`AI_UPSTREAM_ERROR` 表示已进入模型请求阶段，需要根据错误文案排查网络、认证或模型配置。`/health` 仅验证服务存活，不代表模型已接通。

### 开发模式：前后端联调

分别打开两个终端，并在仓库根目录运行：

```powershell
# 终端 1：Express，默认端口 3000
npm run dev:server

# 终端 2：Vite，默认端口 5173
npm run dev:client
```

浏览器访问 `http://localhost:5173/`。Vite 会把 `/api` 请求代理到 `.env` 中 `PORT` 指定的 Express 端口；健康检查地址为 `http://localhost:3000/health`。修改 `.env` 后需要重启对应进程。

### 仅运行前端假 API

如需在后端未启动时单独开发页面，将 `.env` 中的配置改为：

```dotenv
VITE_API_MODE=mock
```

然后重启并只运行 `npm run dev:client`。该模式使用浏览器内置的 14 天脚本，顶部走查面板中的失败注入也只在此模式可用。

### 生产构建与一体化启动

```powershell
npm run build
npm start
```

访问 `http://localhost:3000/`。此时 Express 同时提供构建后的 `client/dist` 和 `/api`，适合现场演示。`npm start` 前必须先执行一次 `npm run build`，代码更新后也要重新构建。

### 局域网访问

开发模式访问 `http://<本机内网IP>:5173/`，一体化启动访问 `http://<本机内网IP>:3000/`。可在 Windows 中运行 `ipconfig` 查找 IPv4 地址；演示设备需连接同一局域网，并允许 Node.js 通过 Windows 专用网络防火墙。localStorage 按协议、主机和端口隔离，因此 `localhost:5173`、内网 IP 的 `:5173` 与 `:3000` 各自拥有独立存档。

### 常用命令

CI 不需要上传 `.env`，也不需要配置 DeepSeek 的 GitHub Secrets。测试启动本地 HTTP 模拟 API，使用虚构密钥与固定数据，覆盖 14 天事件、选择结算、结局、缺少配置、鉴权失败、限流及上游故障。测试限制请求只能访问本次创建的本地服务器，不产生模型调用费用。前端仍按 `server` 模式构建，确保构建产物保留真实后端对接路径。

本地复现 CI 的构建和接口测试：

```powershell
npm run build
npm run test:ci
```

GitHub Actions 还会启动构建后的服务，检查健康接口、前端页面与选择结算。模拟测试不能验证真实密钥、服务商模型可用性或生成质量，这些由开发者在本机单独验证。

| 命令 | 用途 |
| --- | --- |
| `npm run dev:client` | 启动 Vite 开发服务器 |
| `npm run dev:server` | 启动 Express，并在源码变化时重启 |
| `npm run build` | 检查并构建前后端 |
| `npm start` | 启动已构建的一体化服务 |
| `npm run typecheck -w client` | 单独检查前端 TypeScript |

若页面提示网络错误，先访问健康检查地址确认后端已启动，并确认 `.env` 中的 `PORT` 与实际端口一致。若端口被占用，请关闭占用进程或修改配置后重启。刷新后直接进入第 N 天是正常的存档恢复行为。

更详细的页面走查、存档行为和排错说明见 [运行说明](Deploy.md)。
