- 沿用 `campusmock:snapshot` 键名，避免开发阶段已有存档无故失效。

- 区分无存档、损坏存档、不支持版本和浏览器存储不可用；无法读取时保留原始数据，不自动清空。
- 新游戏使用唯一 `gameId`，避免不同局之间的迟到响应相互覆盖。

### 保存与请求接纳

- API 响应只有在成功写入 localStorage 后才成为当前页面状态。
- 写入失败时保留待保存响应并暂停推进；“重试保存”只重试 localStorage，不重新请求模型。
- 客户端生成 `requestId`，Mock API 原样返回，用于确认响应属于当前操作。
- 同时检查请求令牌、`requestId`、`gameId`、当前 `revision` 和 `baseRevision`，旧请求晚到时不采纳。
- 新开局、载入走查状态、清除存档和多标签页冲突都会使进行中的旧请求失效。
- 捕获 API Promise 异常并进入可重试错误页，不会永久停留在加载状态。

### 多标签页与坏档恢复

- 监听浏览器 `storage` 事件。其他标签页改写存档后，本页立即暂停操作并提示重新载入。
- 损坏或版本不支持的存档可先导出原始 JSON，再经二次确认清除并返回开始页。
- 错误页内置处理说明，不依赖仓库链接或外网访问。

### 演示与生产构建

- 开发环境默认显示走查面板。
- 生产构建默认隐藏走查面板；确需演示时设置 `VITE_ENABLE_PROTO_BAR=true`。
- 请求进行中或等待重试保存时，走查面板停止修改状态。

### 前后端对接

- 新增统一 API 适配层，默认通过相对路径请求 Express，也可用 `VITE_API_MODE=mock` 切换到前端假 API。
- 统一前后端的版本号、阶段名、事件、历史记录、结局和错误响应结构。
- Express 校验完整快照及属性重算结果，选择结算由服务端确定性执行。
- Express 可直接提供 `client/dist`，根目录支持统一构建与一体化启动。
- Vite 从根目录读取 `.env`，并将 `/api` 代理到 `PORT` 指定的服务端端口。

## 接口与依赖

- 存档入口统一从 `client/src/storage/index.ts` 导出：`loadSnapshot`、`saveSnapshot`、`clearSnapshot`、`isSnapshot` 和 `STORAGE_KEY`。
- 前端 API 调用签名为 `(snapshot, requestId) => Promise<ApiResult>`；成员 B 接真接口时需要把客户端生成的 `requestId` 放入请求，并在响应中原样返回。
- 成功响应仍包含 `requestId`、`baseRevision` 和完整 `snapshot`。
- `VITE_ENABLE_PROTO_BAR` 只控制生产构建是否包含走查面板，不影响游戏规则和存档格式。
