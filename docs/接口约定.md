# 我的大学日记（CampusMock）接口约定

> 以下约定已由当前 React 客户端与 Express 服务端共同实现。DeepSeek 内容生成尚未接入，现阶段由服务端模拟生成逻辑返回同一结构。

## 共同原则

- 浏览器携带完整游戏快照，服务端校验后返回下一份快照，不依赖服务内存中的持久会话。
- API 密钥和模型提示词由后端管理。
- 模型输出和浏览器数据均做运行时校验，TypeScript 类型不能替代输入校验。
- 规则版本与存档版本独立管理，旧存档不默默套用新规则。
- 所有属性与增减均为整数，允许最终值为负；单次效果使用游戏规则中已确认的范围。
- 接口和存档始终保留完整四维属性；前端隐藏学业与社交属于展示规则，不能通过删减响应字段实现。

## 快照结构

| 字段 | 含义 |
| --- | --- |
| schemaVersion | 存档结构版本 |
| rulesVersion | 本局使用的初始值、增减及分档规则版本 |
| gameId | 本局唯一标识，新游戏重新生成 |
| revision | 状态修订号，每次成功转换递增 |
| phase | `pendingEvent`、`pendingChoice`、`showResult`、`pendingEnding`、`ended` |
| attributes | academics、social、energy、money 四维值 |
| history | 按日期排列的已结算事件、选项标识、结果及实际效果 |
| currentEvent | 当前事件及其所有选项；没有待选事件时为空 |
| ending | 最终值、四个档位及已生成结局；尚未生成时为空 |

以历史长度作为已完成天数，下一事件天数为历史长度加 1，避免多个进度字段不一致。展示结果阶段保留刚完成的记录；完成 14 条历史后只能进入结局。

后端校验历史日期连续、事件标识不重复、已选选项存在，依据初始值和历史效果重算属性，与快照声明的属性比较。不一致时拒绝请求，不直接接受浏览器声明的最终点数。

事件和选项字段见 [游戏规则](游戏规则.md)。历史需要保留用于校验的已选选项效果和用于后续生成的精简文字；未选选项可随历史压缩移除。单纯重算不能识别玩家同时修改历史和属性，首版不承诺防作弊。

## 接口

| 方法与路径 | 请求 | 处理与响应 | 模型调用 |
| --- | --- | --- | --- |
| POST /api/events/generate | requestId、snapshot | 校验快照，生成下一事件及全部选项效果、结果叙述，返回待选择快照 | 1 次 |
| POST /api/events/choose | requestId、snapshot、eventId、optionId | 校验当前事件及选项，累计四维、记录历史，返回展示结果或待生成结局快照 | 无 |
| POST /api/endings/generate | requestId、snapshot | 校验已完成 14 天，按规则计算档位并生成结局，返回已结束快照 | 1 次 |

开局由共享规则初始化并保存，不需要模型调用。第 1～13 天的展示结果阶段，玩家继续时请求生成下一事件；第 14 天结算后先保存待生成结局，再请求结局。

生成事件接口若收到已有未结算事件的快照，直接返回该事件，不重新生成。结局接口若收到已有结局的快照，直接返回保存结果。选择接口若事件已在历史中，返回既有结算；若重复请求提交的是旧快照，则确定性地产生相同的新属性，前端不得再按差值追加一次。

## 响应与失败约定

成功响应包含 requestId、baseRevision 和完整 snapshot。requestId 由前端为每次操作生成，后端在成功或失败响应中原样返回。前端只在请求标识、游戏标识、当前修订号与操作均匹配时保存响应，并以完整快照替换状态；不能重复累加响应中的效果。

失败响应包含 requestId、error.code、error.message、error.retryable。提示使用简体中文，不暴露 API 密钥或原始供应商报错中的敏感信息。

| 错误类别 | 处理 |
| --- | --- |
| 存档格式或规则版本不支持 | 不重试模型，不覆盖原存档 |
| 事件、选项或阶段不合法 | 不修改属性，恢复当前有效界面 |
| 模型超时或临时调用失败 | 保留原快照，提供重试 |
| 模型字段缺失、变化越界或内容截断 | 不接纳半成品事件，提供重试 |
| 结局生成失败 | 保持最终属性及待生成结局阶段，只重试结局 |

前端始终先保存成功响应再推进显示状态；存储失败时保留响应供重试保存，不重复请求模型。进行中的操作使用独立界面状态，不将永久锁写进存档。

前端收到事件后保存全部选项效果，但选择前不渲染数值。结算后只直接展示精力和金钱的增减，学业与社交效果继续写入历史并通过结果文案和后续事件体现。

requestId 用于关联响应，不代表后端具有跨重启的请求缓存。尚未保存的模型响应丢失后可能重新生成；可恢复和不重复结算的保证针对已保存快照及有效的状态转换。
