- 桌面端开始页两侧留白已填，并且**做了 5 套主题、切屏随机换**，避免每一屏两侧长一个样：① 宿舍台阶与上楼的两人 / 亮灯的教学楼与门口的自行车 ② 梧桐林荫道与空长椅 / 银杏树下挂着书包的自行车 ③ 拱形门廊与台阶上睡着的猫 / 摞起的书、摊开的日记和一杯热饮 ④ 看台与躺在跑道栏杆边歇着的人 / 足球门与靠门柱的人 ⑤ 湖心亭垂柳与小桥上坐着的猫 / 石拱桥、桥头长椅与芦苇。取的是「一个人路过时瞥见的校园细节」这一类画面，透明度 .45。
- 位图是透明水彩小景、盖不住下面的矢量，所以位图 `onload` 后给容器加 `has-art`，用 `.scene .side.has-art svg{display:none}` 把兜底图收起来；`onerror` 只 `this.remove()`，不加类，退路自动成立。

- 5 套主题的切换靠 `.scene` 上的 `data-scene` 属性配 CSS 选择器，未选中的整组 `display:none`；随机取值排除上一次的那一套，所以每次切屏都看得见变化。漂浮纸页（共 5 张）和鼠标视差容器放在主题外面，五套共用，切背景时纸页不会跟着消失。
- 顺带修掉一个既有缺陷：两侧远景原本只让出 40px 呼吸位，但纸页用负 `right` 故意探出容器、鼠标视差还能再推 ±17px，实测 901~1100px 之间会压到 560px 正文栏 21~31px。呼吸位改成 100px（`calc(50vw - 380px)`），≥1440px 由 `19vw` 封顶所以桌面观感不变。
- 人眼过了一遍矢量版后重画过三处：第 5 套的亭子白柱在 .45 透明度下几乎看不见（加描边、补栏板）、桥只剩一条细弧线（改成填充的桥身 + 桥面 + 栏杆立柱）、垂柳原本是个箭头形色块（改成树冠 + 下垂枝条）；第 4 套的旗杆原本悬在看台上方 28px，已接到屋脊。换成水彩后这三处只影响兜底图，仍然保留。
- `client/design/README.md`：文件清单与分享注意事项、打开方式、八屏与 `phase` 对照表、`:root` 变量改色对照、动效清单、素材来源与合规提示、已验证与未验证清单。

## 验证记录

- 验证方式：把原型装进固定宽度的同源 iframe，在 390 / 768 / 1280 三档下逐屏切换并用 `getBoundingClientRect()` 量测；本轮改为主页面直接量测 + 截图复核。
- 结果：8 屏 × 3 档均无横向溢出（`scrollWidth > 视口宽` 全为 false，无元素越界）。
- 结果：关掉「设计标注」后逐屏断言可见文字 —— 除结局页外 7 屏均不含「学业」「社交」字样；「待选择」屏不含任何带符号数字，「展示结果」屏只有精力 `−2`，「待生成结局」屏只有精力 `−3`。选择前不泄露效果成立。
- 踩坑记录：这条断言必须先关掉设计标注。标注框里写着「学业 +3、社交 −1 已写入 history，但界面上不展示」，开着标注跑断言会把说明文字当成 UI 文字，误判成泄露。
- 结果：两张 webp 均加载成功（`naturalWidth` 990 / 1040）；把 `src` 改成不存在的路径后，`onerror` 生效、`<img>` 从 DOM 移除、下层 SVG 可见，四层结构顺序为 svg → img → 光晕 → 落叶。
- 结果：结局页横幅 375×180 固定不随视口变化，与正文间距 22px，重叠缺陷已消失。
- 结果（两侧远景 5 套主题）：在 1440 档同源 iframe 里逐套切换量测，5 套全部渲染出 2 组 SVG；48 次切屏随机取样覆盖 1~5 全部主题、连续重复 0 次；淡入动画触发并在 1 秒后回到 `opacity:1`；同一时刻只有 1 套可见、其余 4 套 `display:none`。
- 结果（净空）：把鼠标视差推到最坏值（左组 `--mx=.5`、右组 `--mx=-.5`）后，在 901 / 950 / 1024 / 1100 / 1280 / 1440 / 1920 七档量测，两侧远景外缘（含探出的纸页）与 560px 正文栏的净空全为正数，最小 32px（901 档左侧）、最大 224px（1920 档）；各档 `scrollWidth` 均不超过视口宽；900 / 880 / 390 三档整组 `display:none` 生效。改前同一量测在 901~1100 段是 −21~−31px，即装饰压到正文上。
- 探针又踩一个坑，记下来：判"哪些元素真的在渲染"不能只看元素自己的 `getComputedStyle().display`。藏在 `display:none` 父级里的子元素，自身 computed display 仍然是 `block`，但 `getBoundingClientRect()` 返回全 0，于是"右组最小左边缘"被算成恒定的 0，量出来的空隙全是假的。要么往上逐层查祖先的 display，要么直接用 `getClientRects().length` 过滤。
- 已人眼确认（矢量版那轮）：5 套主题逐套截图看过，第 4、5 套的三处图形缺陷按「已完成内容」里记的方案重画后复核通过；1440 档「待选择」屏带第 5 套背景的整屏截图确认两侧图元落在留白里、不压卡片。
- 验证方式（水彩版这轮）：走查面板处于隐藏状态时浏览器工具截不了图（`visibilityState=hidden`），改用 headless Edge 出图 —— `msedge --headless=new --allow-file-access-from-files --window-size=1440,900 --virtual-time-budget=6000 --screenshot=...`，配一个临时 wrapper 页把原型装进 1440px 同源 iframe、按 `#n` 强制第 n 套主题并等图片 `complete`，量布局仍然用同源 iframe 直接读 rect。wrapper 是临时文件，验证完已删。
- 结果（水彩版 5 套主题）：200 次切屏后十张 `data-src` 全部补齐，`complete && naturalWidth` 10/10、`has-art` 10/10、兜底 SVG 全部 `display:none`；把 `src` 换成不存在的路径后 `<img>` 自行移除且不会加上 `has-art`，手动摘掉 `has-art` 时兜底 SVG 由 `none` 回到 `block`，掉图退路成立。
- 结果（净空，按位图的新高度重测）：901 / 1000 / 1100 / 1280 / 1440 / 1728 / 1920 七档 × 五套主题，左组推到 `--mx=.5`、右组推到 `--mx=-.5`，外缘（含探出的纸页）与 560px 正文栏的净空全为正，左最小 36px、右最小 29px；各档 `scrollWidth` 均不超过视口宽；390 / 760 / 860 / 900 四档整组 `display:none`。
- 修掉的缺陷：`loading="lazy"` 让十张里只有一张真正下载——祖先 `display:none` 的图片不会开始加载，等它变可见也不会补触发。换成 `data-src` + `pickScene()` 按需补 `src` 后十张全通，顺带把首屏体积从 542 KB 压到 88~130 KB。
- 抠图管线两个坑：① `mix-blend-mode:multiply` 去不掉水彩的白底，因为 `.scene` 是 `position:fixed` + `z-index:0` 自成层叠上下文，混合只在这层内部发生、够不到 body 的渐变，所以只能走真透明通道；② `getbbox()` 把 alpha>0 的抠图噪点也算进内容，实测主体只占画面 24%、落到留白里只剩 125px 宽，要先按阈值过滤 alpha 再裁。
- 角标位置不固定：八张在画布角落、整块矩形就能抹掉，但第 4 套左与第 5 套右的角标落在画面中部偏右下，扩大公共矩形会连水彩一起挖穿。第一次凭目测估的框把看台阴影挖掉一块而字还在，最后靠 1:1 网格截图读出像素坐标、按文件单独给框才干净。教训：估坐标不如画网格读网格。
- 只有量尺寸才发现的缺陷：纸页是 `<span>`，原本靠 `position:absolute` 才自动变成块级；为了把视差和漂移分到两层而改成 `position:static` 后，它退回内联元素，而 `aspect-ratio` 对非替换内联元素无效，高度直接塌成 0 —— 补 `display:block` 解决。教训：给 `<span>` 换定位方式时要顺手确认它还是不是块级。
- 探针自身踩的坑记两条，避免下次误判：① 算居中偏移要减 `innerWidth/2` 而不是 `innerWidth`；② 判"装饰是否压到正文"要分左右两组分别比，把两侧元素混进同一个 `Math.max` 会得出恒定 true 的假阳性。
- 已人眼确认：开始页与结局页截图各一张，插画与页面冷色背景、暖色落日光晕协调，落叶与推近动效在位。
- 仍存在的问题：深色模式、超长 AI 文案（>800 字）、精力或金钱为负时的 HUD 表现都还没测；动效只确认了在跑，没测过低端机局域网设备上的帧率。
